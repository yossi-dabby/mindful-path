## 1. תחום השלב

שלב 7 הוא שלב ארכיטקטורה, מיפוי ובקרות בלבד.

- אין יצירה, תרגום, עריכה, מספור או החלפה של טופסי PDF.
- אין שינוי בטפסים בעברית.
- אין הוספת placeholder עבור שפה שאין בה טופס מאושר.
- אין יצירת קטלוג נפרד ל־UI או ל־AI.
- אין שינוי מזהים קיימים.
- תשתית שבע השפות נשמרת: `en`, `he`, `es`, `fr`, `de`, `it`, `pt`.

## 2. מקור אמת יחיד

מקור האמת בזמן ריצה הוא:

`src/generated/therapeutic-forms-index.json`

הקובץ נטען על ידי:

`src/data/therapeuticForms/index.js`

המערך `ALL_FORMS` נבנה מהאינדקס המחולל בלבד. מודולי המקור וה־manifestים משמשים קלט למחולל ואינם קטלוגי runtime מתחרים.

## 3. שרשרת הבנייה

1. מודולים אוצרו תחת `src/data/therapeuticForms/`.
2. manifestים נקראים מתוך `public/forms/`.
3. קובצי PDF קיימים נסרקים כמסלול fallback של המחולל.
4. `scripts/generate-therapeutic-forms-index.mjs` מנרמל ומאמת את הרשומות.
5. נוצר `src/generated/therapeutic-forms-index.json`.
6. ה־resolver מסנן ומחזיר גרסה מאושרת לפי שפה.
7. ספריית הטפסים ומנגנון ה־AI צורכים את אותו מקור אמת.

פקודות השער:

- `npm run generate:forms-index`
- `npm run check:forms-index`
- `npm test`
- `npm run test:e2e`

## 7. מדיניות שפה בזמן ריצה

### ספריית הטפסים

`src/pages/TherapeuticForms.jsx` מציגה רק רשומה שיש לה בלוק של השפה הפעילה ופתרון תקין לנתיב תחת `/forms/`.

- עברית מוצגת ב־RTL.
- יתר השפות מוצגות ב־LTR.
- אין fallback שקט לאנגלית ב־UI.
- שפה ללא טפסים מאושרים מציגה מצב ריק אמיתי.

### Resolver

`src/data/therapeuticForms/resolveTherapeuticForms.js` פועל בהתאמה מדויקת לשפה.

- רשומה לא מאושרת אינה מוחזרת.
- בלוק שאינו PDF תקין אינו מוחזר.
- בקשת שפה ללא וריאנט מתאים מחזירה `null`.
- אין המצאת מזהה, קובץ או כתובת.

### AI

`src/data/therapeuticForms/aiFormsAccess.js` משתמש באותו קטלוג קנוני.

- בקשה רגילה בשפה שאינה אנגלית אינה מקבלת fallback שקט לאנגלית.
- בקשת מזהה שאינו זמין בשפה המבוקשת מחזירה הודעת אי־זמינות והשפות הקיימות.
- סימון טופס מותר רק כמזהה מאושר ומדויק: `[FORM:form-id]`.
- ברירת המחדל היא טופס אחד; עד חמישה רק בבקשה מפורשת למספר טפסים.
- טופס אינו תחליף למסלול חירום.

## 9. פערים מתועדים להמשך

1. `es`, `fr`, `de`, `it`, `pt` נתמכות ארכיטקטונית אך ללא תוכן טפסים מאושר.
2. אין כרגע תוכן מאושר לקהלי מבוגרים, מבוגרים־מבוגרים והורים.
3. רשומות legacy באנגלית אינן כוללות תמיד את מטא־דאטת הווריאנטים החדשה; זו תאימות מכוונת ואין לשנות מזהים כדי ליישר אותה.
4. תיעוד ה־fallback הישן אינו חד־משמעי מול ההתנהגות הקשיחה בפועל של ה־UI וה־resolver. יש ליישרו בשלב ייעודי בלי לשנות התנהגות.
5. הרחבת שפה עתידית חייבת לעבור דרך המחולל והרישום הקנוני היחיד.

## 10. כללי מימוש מחייבים לשלבים הבאים

1. מוסיפים רשומה רק לאחר שקיים קובץ מאושר בפועל.

3. מקשרים וריאנט חדש באמצעות המטא־דאטה התוספתי.
4. אין ליצור טופס ריק, URL מומצא או fallback סמוי.
5. UI ו־AI חייבים להמשיך לצרוך את `ALL_FORMS` בלבד.
6. כל שינוי עובר את מחולל האינדקס ואת בדיקות הבטיחות והפריטטיות.
7. GitHub Actions חייב להחזיר Test Suite ו־Playwright E2E בירוק לפני מיזוג.
